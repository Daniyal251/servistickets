# Архитектура системы

## Обзор

Система представляет собой высоконагруженный сервис продажи билетов, спроектированный для поддержки 2000+ одновременных пользователей.

## Компоненты

### 1. Frontend (Next.js)

**Клиентское приложение (client-web)**
- SSR для SEO оптимизации
- React Server Components для производительности
- Кэширование через React Query
- Оптимистичные обновления UI

**Приложение организатора (organizer-web)**
- Real-time аналитика через WebSocket
- Управление событиями и билетами

**Админ панель (admin-web)**
- Модерация контента
- Системная аналитика

### 2. Backend (NestJS)

**Модульная архитектура:**
- `EventsModule` - управление событиями
- `TicketsModule` - продажа и резервирование билетов
- `OrdersModule` - обработка заказов
- `UsersModule` - пользователи и роли
- `AuthModule` - JWT аутентификация
- `QueueModule` - фоновые задачи

**Оптимизации для высокой нагрузки:**
- Connection pooling через PgBouncer (50 соединений)
- Redis кэш для популярных запросов
- Асинхронная обработка через BullMQ
- Rate limiting на уровне приложения и NGINX

### 3. База данных (PostgreSQL)

**Схема оптимизирована для:**
- Быстрого поиска событий (индексы на status, startDate, city)
- Эффективной фильтрации (composite indexes)
- Масштабирования чтения (read replicas)

**Таблицы:**
- `users` - пользователи с ролями
- `events` - события
- `venues` - площадки
- `tickets` - билеты с QR-кодами
- `orders` - заказы
- `categories` - категории событий

### 4. Кэширование (Redis)

**Используется для:**
- Кэширования популярных событий (TTL: 5 мин)
- Хранения пользовательских сессий
- Блокировки билетов при резервировании (TTL: 10 мин)
- Rate limiting counters

### 5. Очереди (BullMQ)

**Обрабатывают:**
- Отправку email/SMS подтверждений
- Генерацию QR-кодов
- Обработку платежей
- Синхронизацию аналитики

## Поток данных

### Покупка билета

1. Клиент выбирает места → API проверяет доступность в Redis
2. Резервирование на 10 минут → Redis SETEX с TTL
3. Создание заказа → PostgreSQL transaction
4. Оплата → Webhook от платежной системы
5. Подтверждение → Обновление статуса, генерация QR
6. Уведомление → Email/SMS через очередь

### Масштабирование

**Горизонтальное:**
- API: 2-10 подов на основе CPU/memory
- PostgreSQL: Read replicas для SELECT запросов
- Redis: Cluster mode для высокой доступности

**Вертикальное:**
- PgBouncer pool size: 50 соединений на инстанс
- NGINX worker_connections: 1024

## Безопасность

- JWT tokens с refresh mechanism
- Rate limiting: 100 запросов/мин на IP
- Input validation через class-validator
- SQL injection protection через Prisma ORM
- HTTPS в production
- CORS whitelist для frontend доменов

## Мониторинг

- **Prometheus**: метрики производительности
- **Grafana**: дашборды
- **Sentry**: отслеживание ошибок
- **Health checks**: /health endpoint
