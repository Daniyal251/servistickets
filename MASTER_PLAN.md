# 🚀 MASTER PLAN: FairTicket Platform

## 🎯 Миссия продукта
Создание высоконагруженной, отказоустойчивой платформы продажи билетов, которая устраняет главные боли рынка: скрытые комиссии, сложные возвраты, ботов-перекупов и падения при высоком трафике.

## 👥 Ролевая модель и их потребности

### 1. Клиент (Attendee)
*Цель:* Быстро купить билет без стресса и скрытых платежей.
*Боли конкурентов:* Долгая загрузка, скрытые fees на последнем шаге, невозможность вернуть билет, боты выкупают всё за секунды.
*Решение FairTicket:*
- **Прозрачность:** Цена "все включено" показывается сразу в карточке.
- **Скорость:** Покупка в 3 клика, сохранение данных карты.
- **Гарантия:** Легкий возврат (если позволяет организатор) и защищенная перепродажа по фиксированной цене.
- **UX:** Mobile-first интерфейс, работающий даже при плохом интернете.

### 2. Организатор (Organizer)
*Цель:* Продать максимум билетов, контролировать процесс, получать деньги вовремя.
*Боли конкурентов:* Сложный интерфейс создания событий, отсутствие аналитики в реальном времени, проблемы с проверкой билетов на входе.
*Решение FairTicket:*
- **Конструктор событий:** Интуитивный UI для создания событий, загрузки схем залов.
- **Динамическое ценообразование:** Возможность менять цены в зависимости от спроса.
- **Real-time дашборд:** Продажи, выручка, география покупателей.
- **Инструменты входа:** Мобильное приложение сканера для валидации QR-кодов офлайн.

### 3. Сотрудник поддержки (Support Agent)
*Цель:* Быстро решать проблемы клиентов, не переключаясь между системами.
*Боли конкурентов:* Нет доступа к деталям заказа, долгий поиск пользователя, ручные операции возврата.
*Решение FairTicket:*
- **Единое окно:** Поиск по email/телефону/ID заказа показывает всю историю.
- **Быстрые действия:** Кнопки "Вернуть билет", "Аннулировать", "Выслать чек" в один клик.
- **Логирование:** История действий агента для аудита.

### 4. Владелец сервиса (Super Admin / Owner)
*Цель:* Контроль бизнеса, мониторинг нагрузки, финансовая отчетность, безопасность.
*Боли конкурентов:* Непрозрачная статистика, уязвимости к фроду, сложность масштабирования.
*Решение FairTicket:*
- **God Mode Dashboard:** Глобальная карта продаж, текущая нагрузка (RPS), статус сервисов.
- **Финансы:** Автоматическое сплитование платежей (доля платформы vs доля организатора).
- **Безопасность:** Детекция аномалий (бот-атаки, подозрительные транзакции).
- **Управление комиссией:** Гибкая настройка тарифов для разных категорий организаторов.

## 📋 Детальный план реализации (Roadmap)

### Этап 1: Фундамент и Архитектура (High Load Core)
*Срок: 2 недели*
1.  **Инициализация Monorepo (Turborepo):** Разделение на `apps/api`, `apps/web`, `apps/admin`, `packages/ui`, `packages/config`.
2.  **Infra as Code:** Docker Compose для локальной разработки (PostgreSQL, Redis, PgBouncer, MinIO для файлов).
3.  **База данных (Prisma ORM):**
    - Проектирование схемы с учетом нормализации и индексов для быстрого поиска.
    - Настройка миграций.
4.  **Система очередей (BullMQ + Redis):**
    - Очередь на создание заказов (защита от овербукинга).
    - Очередь на отправку email/SMS уведомлений.
    - Очередь на генерацию PDF-билетов.
5.  **Auth Service:**
    - Регистрация/Вход (Email + Password, Google, Apple).
    - JWT токены (Access + Refresh) с ротацией.
    - Ролевая модель (RBAC): Client, Organizer, Support, Admin.
6.  **Rate Limiting & Security:**
    - Настройка NGINX/Cloudflare правил.
    - Лимиты на API запросы на уровне приложения (ThrottlerGuard).

### Этап 2: Ядро продукта (Event & Ticket Engine)
*Срок: 3 недели*
7.  **Модуль Событий (Events):**
    - CRUD событий для организаторов.
    - Категории, теги, геолокация.
    - Загрузка медиа (изображения, видео-тизеры).
8.  **Конструктор Залов (Venue Builder):**
    - Drag-n-drop редактор схем рассадки (SVG/Canvas).
    - Определение секторов, рядов, мест.
    - Привязка цен к конкретным зонам.
9.  **Движок Билетов (Ticketing Core):**
    - Логика "Hold" (временное бронирование места на 10-15 мин).
    - Генерация уникальных QR-кодов (JWT внутри или случайный токен в БД).
    - Статусы билета: Reserved, Paid, Cancelled, Refunded, Used, Transferred.
10. **Система Корзины и Заказов:**
    - Атомарные транзакции при создании заказа.
    - Таймауты на оплату (автоматический релиз мест, если не оплачено).

### Этап 3: Платежи и Финансы (Fintech Layer)
*Срок: 2 недели*
11. **Интеграция Платежных Шлюзов:**
    - Поддержка ЮKassa / CloudPayments / Stripe (абстрактный интерфейс `PaymentProvider`).
    - Обработка webhook'ов об оплате.
12. **Сплитование платежей (Marketplace logic):**
    - Автоматическое распределение средств: % платформы уходит нам, остальное — организатору.
    - Формирование чеков (интеграция с онлайн-кассами по 54-ФЗ).
13. **Система Возвратов:**
    - Автоматический расчет суммы возврата (с учетом комиссии в зависимости от срока до события).
    - Частичный возврат (если билетов в заказе несколько).

### Этап 4: Интерфейс Клиента (Client Web App)
*Срок: 3 недели*
*Стек: Next.js 14 (App Router), TailwindCSS, Framer Motion*
14. **Главная страница и Поиск:**
    - Умный поиск с фильтрами (город, дата, категория, цена).
    - Персонализированные рекомендации ("Похожие события").
15. **Карточка события:**
    - Интерактивная схема зала (выбор конкретных мест).
    - Четкое отображение итоговой цены (без сюрпризов).
    - Отзывы и рейтинг (модерация).
16. **Процесс покупки (Checkout Flow):**
    - Step-by-step мастер: Выбор мест -> Данные участника -> Оплата.
    - Оптимизация под мобильные устройства (Large touch targets).
    - Сохранение черновика заказа в LocalStorage.
17. **Личный кабинет клиента:**
    - Мои билеты (с кнопкой "Добавить в Apple Wallet / Google Pay").
    - История покупок.
    - Профиль и настройки уведомлений.
18. **PWA функции:**
    - Работа офлайн (просмотр купленных билетов без интернета).
    - Push-уведомления о начале продаж и напоминания о событии.

### Этап 5: Интерфейс Организатора (Organizer Dashboard)
*Срок: 3 недели*
*Стек: React, Recharts (графики), React DnD (схемы)*
19. **Дашборд организатора:**
    - KPI: Продано билетов, Выручка, Конверсия просмотра в покупку.
    - График продаж по дням.
20. **Управление событиями:**
    - Мастер создания события.
    - Редактор схем зала (сохранение шаблонов).
    - Управление промокодами и скидками.
21. **Список гостей и Проверка:**
    - Экспорт списков гостей (Excel, CSV).
    - Веб-интерфейс для ручной проверки билетов (если нет сканера).
22. **Финансы организатора:**
    - Заявки на вывод средств.
    - История транзакций и актов.

### Этап 6: Админка и Поддержка (Backoffice)
*Срок: 2 недели*
*Стек: React, Ant Design / MUI*
23. **CRM для поддержки:**
    - Поиск пользователя по любым данным.
    - Просмотр деталей заказа и логов изменений.
    - Принудительный возврат / аннуляция билета с комментарием.
    - Система тикетов (внутренняя переписка).
24. **Панель Владельца (Super Admin):**
    - Управление комиссиями платформы.
    - Верификация организаторов (KYC документы).
    - Глобальный поиск по всем заказам.
    - Блок пользователей и организаторов.
25. **Модерация контента:**
    - Очередь на проверку новых событий перед публикацией.
    - Жалобы пользователей.

### Этап 7: Безопасность, Anti-Fraud и High Load
*Срок: 2 недели (параллельно с другими этапами)*
26. **Защита от ботов:**
    - Интеграция Cloudflare Turnstile или hCaptcha.
    - Анализ поведенческих паттернов (слишком быстрое нажатие кнопок).
    - Лимит на количество билетов с одного IP/карты/аккаунта на популярные события.
27. **Система очереди (Waiting Room):**
    - Страница "Подождите, идет распродажа" при превышении лимита одновременных пользователей.
    - Виртуальная очередь с обновлением статуса через WebSocket.
28. **Аудит и Логи:**
    - Запись всех критических действий (кто, когда, что изменил).
    - Хранение логов в ELK Stack (Elasticsearch, Logstash, Kibana).

### Этап 8: Тестирование и Релиз
*Срок: 2 недели*
29. **Нагрузочное тестирование:**
    - Сценарии в k6: симуляция 2000+ пользователей, пытающихся купить билеты одновременно.
    - Поиск узких мест в БД и коде.
30. **E2E Тесты:**
    - Playwright сценарии: полный путь покупки, возврата, создания события.
31. **CI/CD Pipeline:**
    - GitHub Actions: линтинг, тесты, сборка Docker образов, деплой на staging/prod.
32. **Мониторинг:**
    - Настройка Prometheus + Grafana дашбордов (CPU, RAM, RPS, Latency, DB connections).
    - Алёртинг в Telegram/Slack при ошибках 5xx или высокой нагрузке.

## 🛠 Технологический стек (Final Decision)

| Компонент | Технология | Обоснование |
| :--- | :--- | :--- |
| **Monorepo** | Turborepo | Быстрая сборка, общий кэш, управление зависимостями |
| **Backend** | NestJS (Node.js) | Строгая архитектура, отличная поддержка TypeScript, модульность |
| **Frontend (Client)** | Next.js 14 | SSR для SEO, отличная производительность, PWA из коробки |
| **Frontend (Admin/Org)** | React + Vite | SPA для сложных интерактивных интерфейсов (схемы залов) |
| **Database** | PostgreSQL 16 | Надежность, JSONB для гибких полей, мощная индексация |
| **ORM** | Prisma | Типобезопасность, удобные миграции, автокомплит |
| **Cache/Queue** | Redis 7 | Кэширование сессий, очередей, временных холдов билетов |
| **Connection Pool** | PgBouncer | Критично для 2000+ коннектов к БД |
| **Web Server** | NGINX | Reverse proxy, SSL, Rate Limiting на входе |
| **Real-time** | Socket.io / WS | Уведомления о статусе оплаты, обновление схемы зала в реальном времени |
| **File Storage** | MinIO / S3 | Хранение изображений событий, схем залов, логотипов |
| **Deploy** | Docker + K8s (или Docker Swarm) | Масштабируемость, изоляция сервисов |
| **Monitoring** | Prometheus + Grafana | Визуализация метрик |
| **Logs** | Loki + Promtail | Легковесное логирование |

## 📊 Метрики успеха (KPIs)

1.  **Performance:**
    - TTI (Time to Interactive) < 1.5 сек на мобильных.
    - API Response Time < 100 мс (p95).
    - Устойчивость к 5000 RPS на чтение, 500 RPS на запись (покупка).
2.  **Conversion:**
    - Конверсия из просмотра в покупку > 3%.
    - Отказов на этапе оплаты < 10%.
3.  **Reliability:**
    - Uptime 99.9%.
    - Zero data loss при сбоях.
4.  **User Satisfaction:**
    - Оценка приложения в сторах > 4.8.
    - Время решения обращения поддержки < 15 мин.

## ⚠️ Риски и План mitigation

| Риск | Вероятность | Влияние | Решение |
| :--- | :--- | :--- | :--- |
| **Овербукинг** (продажа одного места двум людям) | Средняя | Критическое | Использование Redis Locks и транзакций БД уровня Serializable для критических участков. Очередь на покупку. |
| **DDoS атака** | Высокая | Высокое | Cloudflare Protection, Rate Limiting на NGINX, автоскейлинг инфраструктуры. |
| **Фрод с картами** | Средняя | Высокое | 3D Secure проверка, лимиты на новые аккаунты, ручная модерация крупных заказов. |
| **Сложность схемы залов** | Средняя | Среднее | Использование готовых библиотек (Konva.js / Fabric.js) вместо самописного canvas с нуля. |
| **Блокировка платежей** | Низкая | Высокое | Подключение нескольких эквайрингов одновременно (failover логика). |
